PART 0 - PURPOSE, GATE AND VERDICT VOCABULARY
================================================================================

0.1 WHAT THIS DOCUMENT IS
-------------------------
Phase C is the master plan's design and mechanics sign-off. It sits between
Phase B (content finalization, now complete for all eight tabs) and Phase D
(build), which the master plan permits "only after explicit confirmation".

This document is that confirmation, item by item. Where the master plan asks
for a decision, this document records one. Where a decision cannot honestly be
made without an input that does not yet exist, the item is marked CARRIED and
its blast radius is stated.

The document is deliberately measurement-led. Contrast ratios were computed
from the actual hex values in variables.css. Route counts were extracted from
the locked plans, not estimated. Duplicate DOM IDs were counted in the shipped
HTML, not inferred.

================================================================================

1.1 FONT STACKS
---------------
Declared in assets/css/variables.css:

  --font-serif : Newsreader, Source Serif 4, Georgia, Cambria, Times New Roman
  --font-sans  : Inter, -apple-system, BlinkMacSystemFont, Segoe UI, Roboto,
                 Helvetica Neue, Arial
  --font-mono  : JetBrains Mono, SF Mono, Consolas, Courier New

FINDING: the repository vendors no webfont files. assets/ contains css, js and
pdf only. The named families resolve only if the reader happens to have them
installed; otherwise the stack falls through to Georgia, Segoe UI and Consolas.

DECISION 1.1 - LOCKED
  Ship the declared stacks unchanged and add no webfont dependency in Phase D.
  Rationale: a static archival site should not block first paint on a font CDN,
  and self-hosting three families would add roughly 300-600 KB to a project
  whose entire HTML payload is currently under 75 KB. The serif/sans/mono
  hierarchy survives on system fallbacks.

CONSEQUENCE TO ACCEPT
  Typography will differ slightly between a machine with Newsreader installed
  and one without. This is acceptable for an editorial archive and must not be
  "fixed" by pinning a webfont later without a new version of this document.

1.4 TYPOGRAPHIC RULES (BINDING)
-------------------------------
  1. Exactly one h1 per page.
  2. Heading levels never skip. h2 follows h1, h3 follows h2.
  3. Body measure is capped at --max-width-article (780px), targeting 65-75
     characters per line.
  4. No all-caps body text. Uppercase is restricted to kickers, badges and
     table headers.
  5. No text justification. Ragged-right only.
  6. Emphasis uses <em> for titles of works and first-use foreign terms;
     <strong> for names, dates and critical findings. No bold paragraphs.
  7. No font sizes set inline except where the shipped homepage already does
     so for legacy compatibility. New markup must use tokens.

5.4 THE TWO-TIER ANCHOR MODEL AND THE NAVIGATION CONTRACT
---------------------------------------------------------
This is the central route finding of Phase C. It was not visible until the plan
anchor declarations were parsed rather than assumed.

5.4.1 THE TWO TIERS

  TIER 1 - PAGE-LEVEL SECTION ANCHORS
    Exactly 15. One per navigable section, owned by the page shell.
    These are the navigation targets. They exist so that navigation always
    lands on a stable, page-authored section boundary regardless of how the
    underlying content plan is subdivided.
    Count: 15 Tier 1 anchors across 6 pages.
      - 13 content-page anchors (context 2, case 3, analysis 3, impact 5),
        compared against plan declarations in 5.4.3.
      - 2 sources-page anchors (#key-sources, #methodology), specified in
        Part 7.11. No plan declares them; they are defined here.

  TIER 2 - PLAN-DECLARED DETAIL ANCHORS
    Declared inside the locked plans, in two formats:
      (a) single-line declaration:
            Anchor: #slug (Aliases: #a, #b)
      (b) concordance table row:
            | Section | #canonical | #alias, #alias | ... |
    Parsed counts, canonical plus declared aliases:
      context   36
      case      98
      analysis  93
      impact   153
    These anchors are content addresses. They belong to the plans.

DECISION 5.4 - LOCKED
  Tier 1 and Tier 2 are separate namespaces. A Tier 1 anchor never replaces or
  renames a Tier 2 anchor. Where both name the same block, the outer sectioning
  element carries the Tier 1 id and an immediately nested element carries the
  Tier 2 id. Both resolve.

  Consequence: navigation is stable even when a plan's internal section naming
  changes, and plan cross-links stay valid even when navigation is restructured.

5.7 ALIAS POLICY
----------------
Four categories of alias, each with a fixed mechanism.

  CATEGORY A - PAGE ALIAS
    A logical path that names another page or a page subsection.
    Example: /topics/systemic-failures
             -> analysis.html#topics-systemic-failures
    Mechanism: build-time rewrite of the logical route to the physical target.
    No DOM alias needed.

  CATEGORY B - SECTION ALIAS
    A second name for a block that already has a canonical Tier 2 anchor.
    Example: #investigation -> the case plan's #investigation block
    Mechanism: the element emits its canonical id, and an .anchor-alias span
    with the alias id is nested immediately inside it.

  CATEGORY C - TEMPLATE TOKEN
    A placeholder that is not a route at all.
    Example: #victim-slug
    Mechanism: none. Excluded from the registry and from link validation.

  CATEGORY D - PAGE-LEVEL WRAPPER
    A Tier 1 anchor that no plan declares, emitted by the page shell so that
    navigation and inbound cross-tab links resolve.
    Example: #offense-series on case.html
    Mechanism: the page adds a wrapper element carrying the id. Additive only;
    no plan anchor is renamed or removed.

DECISION 5.7 - LOCKED
  Aliases are additive and never replace a canonical anchor. No locked plan is
  edited to remove a variant. No shipped nav anchor is renamed.

7.2 DECISION: A PERMALINK LAYER, NOT A RENUMBERING
--------------------------------------------------
DECISION 7.2 - LOCKED

  1. No tab is renumbered. Every local number keeps its current meaning
     forever.
  2. A canonical identifier is added as a PERMALINK, not as a replacement
     number.
  3. The canonical ID is stable, human-readable and derived from the source
     itself, not from its position in any list.
  4. /sources.html presents two views: by tab (local numbers preserved) and by
     source (deduplicated, no numbers assigned).
  5. A build-time generator produces the canonical map and fails the build if
     any local entry cannot be mapped.

This gives one resolvable identity per source without touching a single locked
file.

7.6 DEDUPLICATION RULES
-----------------------
Two entries are the SAME source when any of these hold:

  1. Identical normalized URL. Normalization strips protocol, www., trailing
     slash, query tracking parameters and fragment.
  2. Identical court case number and court.
  3. Identical statutory section citation.
  4. Identical outlet plus identical publication date plus identical headline.
  5. Identical DOI.

Two entries are NOT merged when:
  - Same outlet, same date, different headline (letter suffix applies).
  - Same event, different publication (each is its own source).
  - A retrospective and a contemporary piece on the same event.

The generator MUST emit a report listing every merge it performed and every
near-miss it declined, so the deduplication is auditable rather than silent.

7.7 DISPLAY NUMBERING
---------------------
  ON ARTICLE PAGES
    Local numbers only. overview.html uses [1]-[41]; victims.html uses
    [1]-[27]; and so on. Unchanged from the locked plans.

  ON /sources.html, BY TAB VIEW
    One section per tab, each reproducing that tab's local register in order.
    Numbers restart per section. This mirrors the locked plans exactly.

  ON /sources.html, BY SOURCE VIEW
    No numbers at all. Entries are ordered by tier, then by canonical ID.
    Each entry shows its canonical permalink and a list of "cited as" locators.

DECISION 7.7 - LOCKED
  No global display number is ever assigned. A source is addressed by
  permalink, never by a master ordinal. This removes an entire class of future
  renumbering error.

7.8 CITATION DISPLAY MODES
--------------------------
MODE A - GRANULAR (article pages)
  A superscript [n] per claim cluster, resolving to a page-foot footnote.
  Use for: overview, victims, timeline, context, case, analysis, impact.
  Density rule: no more than one superscript per sentence, placed at the end
  of the cited clause, immediately after punctuation.

MODE B - BLOCK (homepage)
  No superscripts. Each homepage module ends with a single line:
    "Sources for this section: [list of links]"
  Use for: index.html feature, milestone table, research inquiries.
  Rationale: the homepage is a front page, not an article. Twenty superscripts
  in a 300-word feature is visual noise and undermines the expandable layout.

MODE C - ATTRIBUTIVE (contested claims, any page)
  A named attribution in prose plus a footnote:
    "According to the FBI teletype, officers arrived at approximately 11:30
     p.m. [1]"
  Use whenever a claim is ATTRIBUTED or DISPUTED under the certainty tiers.
  This is mandatory for expert testimony and for Dahmer's own statements.

7.9 FOOTNOTE MARKUP CONTRACT
----------------------------
REQUIRED SHAPE

  Citation:
    <sup class="citation"><a href="#fn-7" id="ref-7">[7]</a></sup>

  Second and later citations of the same footnote on the same page:
    <sup class="citation"><a href="#fn-7" id="ref-7-2">[7]</a></sup>
    <sup class="citation"><a href="#fn-7" id="ref-7-3">[7]</a></sup>

  Footnote:
    <li id="fn-7">
      Citation text.
      <a class="footnote-backref" href="#ref-7"
         aria-label="Back to reference 7">&#8617;</a>
      <a class="footnote-backref" href="#ref-7-2"
         aria-label="Back to reference 7, second occurrence">&#8617;</a>
    </li>

RULES
  1. Every id is unique in the document.
  2. Every footnote lists one backref per citation occurrence.
  3. Every footnote ends with a permalink to #src-<canonical-id>.
  4. Footnote text is the full citation on first use; short form on later
     pages is not permitted because each page is an independent document.
  5. No footnote may be defined but never cited, and none cited but undefined.

7.10 DEFECT FOUND IN THE SHIPPED PAGE
-------------------------------------
overview.html contains 83 id attributes but only 67 unique values. Sixteen are
duplicates:

  ref-7  x4     ref-1  x4     ref-17 x3     ref-3  x3
  ref-9  x2     ref-13 x2     ref-5  x2     ref-4  x2
  ref-6  x2     ref-2  x2

CONSEQUENCE: every backref of type ref-N jumps to the FIRST occurrence of that
ID, not the occurrence the reader came from. On a long page this means clicking
the back arrow after footnote 7 can return the reader to an unrelated earlier
citation. It also fails HTML validation.

CLASSIFICATION: BLOCKING for overview.html only. It does not block any other
page and does not block Phase D from starting on sources.html.

FIX (Phase D, when overview.html is rebuilt): apply the ref-N-M suffix scheme in
7.9 and emit one backref per occurrence.

7.11 /sources.html ARCHITECTURE
-------------------------------
TWO VIEWS, ONE PAGE, NO JAVASCRIPT REQUIRED

  VIEW 1 - BY TAB (default)
    Nine sections, matching the nine pages. Each section reproduces that tab's
    locked register with its local numbers. Anchor: #sources-<tab>.
    A source cited in three tabs appears three times, each time linking to the
    same canonical anchor. That redundancy is intentional: readers arrive by
    tab, not by bibliography.

  VIEW 2 - BY SOURCE (deduplicated)
    Five tier sections, no numbers. Each entry carries the canonical permalink
    and a "cited as" list. Anchor: #src-<canonical-id>.

  VIEW SWITCH
    Implemented as anchor links to #by-tab and #by-source. CSS :target reveals
    the selected view. No JavaScript, no fetch, works over file://.
    Default view is #by-tab. If neither target is present, both views render
    sequentially rather than hiding one, so the page degrades safely.

REQUIRED PAGE ANCHORS
  #key-sources        (nav target; points to the by-source view)
  #methodology        (nav target; the editorial standards section)
  #by-tab
  #by-source
  #sources-overview, #sources-victims, #sources-timeline, #sources-context,
  #sources-case, #sources-analysis, #sources-impact

  RULES

PART 8 - IMAGE TREATMENT (FINAL)
================================================================================

8.1 GOVERNING POLICY
--------------------
The archive is a documentary record about people who were killed and about the
institutions that failed them. Imagery serves identification, context and
accountability. It does not serve atmosphere.

8.2 PERMITTED CATEGORIES
------------------------
  1. Redacted archival documents (FBI pages, charging documents, docket sheets)
     where the source is public and the redaction is already part of the record.
  2. Architectural and streetscape images of locations that are public and
     non-sensational: the Oxford Apartments site before demolition, the
     courthouse, the Milwaukee streetscape.
  3. Maps and diagrams produced by this project (segregation maps, timelines,
     institutional flow diagrams).
  4. Typographic plates carrying dates, statutes or document excerpts.
  5. Photographs of public events (courthouse arrivals, council meetings) where
     rights are documented.

8.3 PROHIBITED CATEGORIES (BINDING)
-----------------------------------
  1. Crime-scene photographs of any kind.
  2. Autopsy, remains, or forensic imagery, including redacted versions.
  3. Photographs of victims' remains or of the interior of Apartment 213
     showing remains.
  4. Prison photographs of the perpetrator presented for spectacle.
  5. AI-generated or composited "reconstructions" presented as archival.
  6. Any image whose rights basis is undocumented.

8.4 PER-ASSET CONTRACT
----------------------
Every shipped image must carry, in this order:

  <figure class="visual-container">
    <img src="..." alt="[content description]" width="..." height="...">
    <figcaption class="visual-caption">
      [Caption text]. [Credit]. [Date]. [Rights status].
    </figcaption>
  </figure>

  ALT TEXT RULE
    Describe what the image shows and why it matters. Never begin with "Image
    of" or "Picture of". Decorative images use alt="" and are not figures.

  RIGHTS RULE
    Rights status is one of: PUBLIC DOMAIN, GOVERNMENT RECORD, LICENSED,
    PERMISSION GRANTED, FAIR USE (with rationale). "UNKNOWN" is not permitted
    and means the asset does not ship.

  DIMENSION RULE
    width and height attributes are mandatory to prevent layout shift. Use the
    intrinsic ratio; CSS scales.

8.5 RIGHTS AND DIGNITY
----------------------
  - Victim portraits are permitted only where the family or a licensed
    publication has made them public, and only with a credit.
  - No image may be used to illustrate a theory. Images illustrate records.
  - The non-graphic standard in 08_sources_by_tab is restated here as binding
    for every page, not only Victims.

D-01  CHEMICAL DRUM CAPACITY
  Conflict:  55-gallon vs 57-gallon.
  Evidence:  FBI Part 7 records a 55-gallon drum. The source directory's own
             cover note (08_sources_by_tab.txt, line 696) says 57-gallon.
             overview.html line 205 says 57-gallon.
  Problem:   The project contradicts itself, and the live page asserts the
             value the primary record does not support.
  STATUS:    DECIDED
  RULE:      Display 55-gallon, attributed to the FBI record. Do not repeat the
             capacity in body prose unless the sentence is about the drum
             specifically. If a note is wanted, say that contemporaneous
             reporting varied. The 57-gallon figure is retired.

  Conflict:  FBI interview record says "around 1986 or 1987". Last-seen date is
             September 15, 1987.
  STATUS:    RETAINED

             with the uncertainty marker carried in the Timeline and Victims
             tabs. Do not compute an age from an assumed death date.

  STATUS:    RETAINED
  RULE:      Table 1 already states both with attribution. Keep that wording.
             Prose should say "early 1988" and link to Table 1.

  STATUS:    RETAINED

             without the asterisk convention.

  STATUS:    RETAINED
